# tools — 上架前的檢查

這六個 Python 檢查 ＋ 三支 Node 腳本（模擬／資料驗證／改壞測試）＋ 一個瀏覽器 harness，是課程上架前的檢查工具。
**每一個都抓得到別人抓不到的東西**，所以請六個都跑，不要只跑靜態的。
（前兩輪審查時它們寫在暫存目錄裡，事後都不見了，只好重寫兩次 —— 所以這次進版控。）

先開一個本機伺服器（瀏覽器 harness 需要）：

```bash
cd <repo root>
python3 -m http.server 8765
```

## 1. inline script 語法檢查

```bash
python3 tools/check_syntax.py .   # 含 tools/sweep.html
```

把每一頁的 inline `<script>` 抽出來丟 `node --check`。抓語法錯誤 —— 頁面壞掉時
瀏覽器只會靜靜地什麼都不做，靜態讀檔看不出來。

## 2. i18n 檢查（綁定 ＋ 中文殘留 ＋ key 對應 ＋ 英文字典裡的中文）

```bash
python3 tools/check_i18n.py $(find . -name '*.html' -not -path './tools/*' | sort)
```

四種問題一次抓（對應 teaching-framework.md §五之一）：

- `BIND` —— markup 引用了兩本字典裡都沒有的 key（key 對應檢查永遠抓不到）
- `LEAK` —— 中文文字節點掉在所有 `data-i18n` 元素之外（用 tag stack 判定，
  巢狀 `<strong>`／`<br>` 不算；void 元素不進 stack —— 這個 bug 曾經藏了 19 個真殘留）
- `PARITY` —— zh／en key 沒有一一對應
- `EN-CJK` —— `I18N.en` 裡有中文。**目前有 39 筆是刻意的**（中文數字、八折這類
  「中文本身就是教材」的字串），`en.btn` 的 `'中'` 也是正常的。

## 3. 題庫與選項檢查

```bash
python3 tools/check_quiz.py $(find . -name '*.html' -not -path './tools/*' | sort)
```

- 題庫張數（`qs` 6 ＋ `qsAdv` 4 ＋ `qsBoost` 2）、選項數、**zh／en 正解索引一致**
- `EQVAL` —— 同一組選項裡有兩個「值」相同的項（有理數比較，**含單位**：
  `1 公克` 和 `1 公斤` 不相等）。目前有 8 筆是 §六之二 的合法例外
  （反向題 `percent`、記法就是考點 `rounding`、題幹已寫「記得約分」`fraction-multiply`）。

⚠️ **這支檢查的數值解析在 2026-08-28 修好三個 bug，在那之前等值檢查長期半殘**：
  ① `NUM` 正規式裡的 `[+-−]` 是**字元範圍** `+`(U+002B)~`−`(U+2212)，把 0~9 全包進去 ——
  `13/5` 被讀成「符號 1、分數 3/5」，於是 13/5 和 23/5 被判成同一個值（假警報），
  而真正等值的兩位數選項反而驗不到。要寫成 `[+\-−]`。
  ② `m.group(n) in '-−'` 在沒有符號時是 `'' in '-−'` ＝ **True**，一律當成負數。
  要用 `in ('-', '−')`。
  ③ 不認得**英文帶分數**（`1 2/5`），所以 `1 2/4` 和 `1 1/2` 的等值從來沒被驗過。
  **改完要用單元輸入直接印一次解析結果**（`value_unit('1 2/4')` 應該是 `3/2`），
  不要只看全站數字有沒有變。

## 3b. 給家長那一頁的五段格式

```bash
python3 tools/check_parents.py $(find . -name parents.html | sort)
```

檢查 `parents.html` 有沒有真的回答家長要的五件事（teaching-framework §六之一）：
五段齊備、四個可觀察的行為、三個不需教具的活動、每個迷思都配一句**有引號、家長可以照著念**
的話、精熟標準寫出遊戲名稱與 2/3 門檻、只有語言切換一個互動、可列印。

早期手寫的 29 頁鍵名各自不同，只跑通用檢查並印出 `NOTE:`（不是失敗）。

**2026-08-26 起還檢查「延伸資源」區塊**（teaching-framework §六之四），而且是在
「早期手寫頁提前 return」**之前**跑 —— 全站 60 頁都要有這一段，不分新舊：

- **這一段是用 `html.parser` 解析的，不是用正規式掃 markup。** 三輪 codex 審查裡，
  「用正規式讀 HTML」是唯一反覆製造 fail-open 的來源：`<A HREF=…>` 大寫標籤看不到、
  引號值裡面塞 `title='href="…" rel="…"'` 可以假冒屬性、
  整個假區塊藏在 HTML 註解裡也能過。換成解析器之後這三種一起消失
  （註解根本不會進 `handle_starttag`），屬性名稱也由解析器正規化。
- 整段住在**自己的容器** `<div class="resblock">`，容器裡**不可以有巢狀 `<div>`**；
  剛好要有一個容器，多一個少一個都報錯。
- **屬性照名字比對**：`data-href`／`data-rel`／`data-target` 不會被當成
  `href`／`rel`／`target`，同一個屬性重複出現也會報錯。
- **每一列的每一個 `<a>` 都驗**（不是只驗第一個，描述裡多塞的連結也算）：絕對 https、
  `target="_blank"`、`rel` **拆成 token** 後必須同時有 `noopener` 與 `noreferrer`
  （`rel="notnoopener noreferrerx"` 這種字串包含法會被擋掉），
  **而且必須落在這一列自己的網域上**。`<li>` 之外的落單 `<a>` 也會被抓到。
- **列鍵與網域綁定**：`r1`＝junyiacademy.org、`r2`＝khanacademy.org、`r3`＝youtube.com、
  `r4`＝tcool.cc，網域用 `urlparse().hostname` 比對（`junyiacademy.org.evil` 會被擋掉）。
  **`r1` 與 `r4` 是必要的**；`r2`／`r3` 可以缺（4 課沒有誠實對得上的 Khan 單元、
  50 課沒有 Numberblocks），但**只要出現就必須是上表裡的那一列**。列的順序固定 r1→r4。
- **標題與描述的編號必須一致**：`r1t` 配 `r1d`，不可以配 `r2d`；同一個鍵不可以出現兩次。
- `s6`／`s6p1`／`s6note` 三個鍵都要真的綁在 markup 上，**每個鍵在 zh 與 en 兩本字典都查得到**，
  **英文字典的值不可以有中文**（平台名要羅馬拼音）。
- `s6note` 中英文都要寫出**日期**（`連結最後檢查：YYYY-MM-DD`／`Links last checked …`）
  **和第三方免責那句話** —— 那是安全聲明，不是裝飾，所以兩件事分開驗。
  日期還要是**真的日曆日**（`2099-99-99` 會被擋）且中英文寫的是同一天。
- **英文殘留檢查會先把 `\uXXXX`、`\u{...}`、`\xNN` 還原**再判 —— 不然 `"\u4e2d\u6587"`
  畫面上是中文、檢查卻看不到。三個要注意的地方：
  ⚠️ 還原**不能**用 `codecs.decode(..., 'unicode_escape')` —— 那條路徑會把真正的中文字
  丟掉，變成整條檢查靜靜 fail open（第二輪審查抓到的）；
  ⚠️ 要看**反斜線的奇偶**，`\\u4e2d` 是字面文字不是逃逸，不然會誤報；
  ⚠️ surrogate pair 要合併回一個字。

斷言全部釘在**產生出來的 markup** 上，不是釘在樣式上 —— 改 CSS 不會讓檢查靜靜消失。
**25 筆改壞測試全過**（23 筆必須噴錯 ＋ 2 筆必須**不**噴錯），涵蓋三輪 codex 審查提出的
每一種 fail-open：只從 en 字典拿掉一個鍵、`r1t` 配 `r2d`、描述裡多塞一個指向別的網域的連結、
`<A HREF>` 大寫標籤、引號值裡假冒屬性、`data-href` 仿冒屬性、重複的 `rel`、
`rel` 的 token 詐術、仿冒網域 `junyiacademy.org.evil`、`\u4e2d\u6587` 與 `\u{4e2d}` 逃逸、
不存在的日期、中英文日期不一致、`<li>` 外的落單連結、兩個容器、巢狀 `<div>`。
兩筆「必須不噴錯」是：**藏在 HTML 註解裡的假區塊**（不可以被當成真的）、
**`\\u4e2d` 這種字面文字**（不可以誤報成中文殘留）。

## 3c. 課程清單與堂數

```bash
python3 tools/check_lessons.py .
```

首頁與年級頁的「N 堂課」都是**算出來的**，不是手寫的（2026-08-25 起）：

- 年級頁的 `{N}` = 該頁自己的 `.lesson` 課程卡數量 —— 不依賴任何外部檔案，
  畫面上有幾張卡就是幾堂課，結構上不可能對不上。
- 首頁徽章與 `{N5}`（跨年級引用）= `lessons.js` 裡的 slug 數量。
  載不到 `lessons.js` 時，首頁徽章**整個藏起來**、`{N5}` 顯示 `?` ——
  寧可不顯示，也不要顯示錯的數字。

這支腳本盯的是剩下的漂移風險：`lessons.js` 對不上磁碟（新增課程忘了登記）、
年級頁卡片數對不上實際課程數、課程缺頁，以及**有人把堂數寫死回頁面裡**
（`[HARDCODED]`）。起因：首頁二年級長期停在「1 堂課開課中」，實際已有 2 堂。

## 3d. 產生器模擬與課程資料驗證（Node，2026-08-25 起）

```bash
node tools/simgen.js grade-2/math/add-sub/review.html 30000
node tools/verify_lesson_data.js grade-2/math/add-sub/index.html
```

`sweepOptions` 連按十批只看得到千分之幾的參數空間。**`simgen.js` 把 `review.html` 的
「工具 ＋ GENS」區塊切出來（`/* ---------- 工具 ---------- */` 到 `/* ---------- 出一批`
之間，那段不碰 DOM）丟進 Node 跑幾萬批**，每一批中英各檢查一次：

- 選項數、`opts[ans]` 真的等於 `correct`、沒有垃圾字串
- **兩兩比對**選項的值（兩個誘答彼此相等也算缺陷，不是只比對正解）
- 每個選項都在**這一課自己的數字範圍**裡（`RANGE` 表，預設 0~999）
- **每個產生器一組不變條件**（`INVARIANTS`）：解釋說「個位不夠減要退位」，
  資料就必須真的不夠減。**沒有定義不變條件的產生器會直接被判失敗**（`NO INVARIANT DEFINED`）
  —— 換課程時請把 `INVARIANTS` 與 `RANGE` 改成那一課的
- **誘答不可以把題幹的數字抄回來**（`44 + 10` 的選項裡出現 44）
- **解釋引用的提示詞必須真的在題幹裡**（why 說「一共」，題幹卻問「現在有幾元」）

`verify_lesson_data.js` 驗 `index.html` 的靜態資料：三層題庫的算術（能從題幹解析的
一律重算一次）、zh/en 的 `ans` 一致、選項值不重複、正解位置沒有全押同一個、
以及該課的範例資料與遊戲關卡。選項通常是字串；`grade-1/shapes` 的靜態題把選項寫成
形狀描述物件（畫成圖），去重時用 JSON 字串比（兩個 `{kind:'circle'}` 也算重複），
物件的語意由那一課的 `data.check` 自己驗（2026-09-15）。

**每一課的檢查設定住在 `tools/checks/<grade>-<slug>.js`**（2026-08-25 起；在那之前
add-sub 的設定是寫死在腳本裡的，換課程就得改壞上一課）。兩支腳本都從課程路徑推出
key（`grade-2/math/time/review.html` → `tools/checks/grade-2-time.js`），**找不到設定
就直接報錯** —— 沒有設定的課程不算驗過。一個設定檔匯出三塊：

- `sim.INVARIANTS`：每個產生器一組「解釋說了什麼，資料就必須是那樣」的不變條件。
  沒定義的產生器會被判 `NO INVARIANT DEFINED`。
- `sim.expectedCorrect(d, genId, lang)`：**正解字串的第二套實作**，只用 `make()` 留下的
  原始參數重算，完全不呼叫 `review.html` 的格式化函式。拿產生器自己的格式化函式來比
  等於自己比自己 —— 格式化寫錯（把 31 天印成「30 天」）時不變條件、形狀檢查、
  相等檢查會一起錯過。沒定義的課，選項必須就是 `String(d.correct)`（add-sub 那種純數字）。
- `sim.optionOk(s, genId, lang, isCorrect)`：這一課的選項長什麼樣、範圍多少。
  **正解與誘答分開驗** —— `dateAfter` 的「7 月 33 日」是刻意的誘答，但正解永遠是合法日期。
  範圍要從課程自己的規則推出來（時 1~12、分 0~59、月長只有 28/29/30/31、
  `weeksToDays` 的 k 是 2~5 所以天數上限 42），不要隨手給一個大數。
- `sim.optCount` / `data.optCount`：這一課一題有幾個選項。**沒寫就是 4** —— 二、四年級
  全部都是 4 選項，所以既有的設定檔一個字都不用動。一年級是 3 選項（給一年級的孩子，
  選項少一點才讀得完），有些題型是 2 選項（是非／二選一），所以可以寫成
  `3`、`[2, 3]`、或 `{ 產生器id: 3, '*': 4 }`；`data` 那邊的 key 是題庫名
  （`qs`／`qsAdv`／`qsBoost`），例如 `grade-1-two-digit` 是
  `{ qs: 3, qsAdv: 3, qsBoost: 2 }`。
  ⚠️ **混用題型的課要逐一列出產生器**，不要圖方便寫成 `[2, 4]` ——
  那樣其他產生器哪天掉到 2 選項也不會有人發現（`grade-1-length` 就是逐一列出那五個
  「比比看」產生器）。
  ⚠️ 解析是 **fail closed** 的：壞掉的值（`0`、負數、空陣列、字串、小數、超出 2~10、
  過長的清單）一律直接丟錯，不會默默退回預設值。
  ⚠️ 「**沒寫**」和「**寫了但值是 `null`**」是分開處理的：整個不寫 → 預設 4；寫成
  `optCount: null` 或 `{ someGen: null }` → 報錯。後者是打錯字或值被刪掉，如果默默
  退回 4，那個產生器的選項數檢查就靜悄悄失效了 —— 而且因為平常就是綠的，
  沒有人會發現它已經不在看了。
  ⚠️ map 的查找用 `hasOwnProperty`，**不是 `in`** —— `in` 會走原型鏈，繼承來的數值會被
  當成設定值放行，而產生器剛好叫 `constructor`／`toString` 時又會撈到內建屬性而誤報。
  改用 `hasOwnProperty` 之後，這種名字就跟其他沒列到的 key 一視同仁：有寫 `'*'` 就用
  `'*'`，沒寫才是預設 4。
  ⚠️ 兩支腳本都在**開始檢查之前**就把 optCount 全部解析完：`simgen.js` 用 `GENS` 建
  `ALLOWED_OPTS`，`verify_lesson_data.js` 用三個題庫名建一份同名的表，兩者都在進入
  各自的迴圈**之前**。設定檔寫壞時若在迴圈中途才丟錯，那是未捕捉例外 ——
  已經收集到的 `problems` 一筆都印不出來，畫面只剩 stack trace，看起來像「工具壞掉」
  而不是「這一課有 N 個缺陷」。守門員不可以這樣壞。
- `sim.blockStart`：切片起點。預設是「工具」那一段的註解；少數課的 `fmt()` 會用到
  更前面宣告的文字表（`grade-2/numbers` 的 `TXT`：題幹要印「百位／十位／個位」），
  那種課用這個把起點往前移。**往前擴的那一段必須也不碰 DOM**，
  不然這裡跑不起來 —— 這不是萬用逃生門，只允許「純資料」往前擴。
- `sim.renderCheck(d, q, lang, genId)`：拿**渲染出來的那一題**再驗一次。
  2026-09-15 起一年級三課示範了三種「把畫面量回來」：`grade-1-money` 把 stemPic／optPics 的硬幣
  加起來和選項的字比；`grade-1-clock` 從 stem 裡 `<svg>` 的兩條 `<line>` 讀出角度、換回幾點幾分
  （時針必須在 (h + m/60) × 30°），再和正解比；`grade-1-shapes` 從形狀描述重算頂點、邊數、直角數與
  對角線（長方形轉一轉會不會畫出 200×200 的畫布）。三份都不讀課程算好的 count／correct。
  `INVARIANTS` 只看得到資料，看不到題幹與解釋，可是題幹是拼出來的 ——
  `grade-2/multiply` 的連加題會印出 b 個加項，那個數量必須真的等於 b，
  不然孩子看到的是另一道題（資料層全對、模擬全綠，只有數畫面上的字才看得到）。
- `sim.stemEchoOk`：哪些「把題幹的數字放進選項」是刻意的迷思誘答。值可以是布林，
  但**建議寫成謂詞** `function(d, opt, lang, idx)`，只放行那一個值 ——
  整個產生器全開的話，不小心抄回別的數字也會被一起蓋掉。
  課程那一側對應的做法是 `makeWrongs(correct, candidates, avoid)` 的 `avoid`（題幹數字先當成
  已用過，只留 `avoidExcept(題幹數字, [刻意的那一個])`），見 framework §六之三第 4 點；
  一年級 `number-bonds`／`add-sub`／`two-digit`／`pattern`／`length` 五課是範本（2026-09-14）。
  兩邊各自獨立地說出「哪一個是刻意的」——這裡掃的是渲染出來的題幹，不讀課程的 avoid。
- `data.check(data, I18N, fail, src)`：那一課自己的範例資料與遊戲關卡。
  第四個參數 `src` 是**整份 index.html 原始碼**，給那種只有在原始碼層才驗得到的
  不變式用（例如「這句旁白必須是從座標算出來的，不可以寫死成某一筆的索引」）。
  舊設定檔只宣告三個參數，多傳一個不影響它們。
- `breaks`：刻意改壞的清單，見下。

通用的那幾條留在 `simgen.js` 裡，所有課共用：選項數（預設 4，要改用上面的 `optCount`）、
`opts[ans]` 等於獨立算出來的正解、
兩兩不等值、誘答不抄題幹、解釋引用的提示詞真的在題幹裡、`undefined`／`NaN`、
**中文與數字之間要有空格**、**標點不可以連兩個**（英文的 `7:00 p.m.` 後面再補句點會變 `p.m..`）。
後兩條都掃「畫面上真正看得到的文字」：`<svg>` 整塊拿掉、會換行的標籤補一個空白、
行內標籤直接拿掉不補空白（`共<strong>5</strong>個` 畫面上是「共5個」），而且**連選項一起掃**。
最後兩條都是「資料層全對、模擬全綠，只有把句子印出來才看得到」的那一類 ——
產生器的句子是拼出來的，一定要看渲染結果。
批數不是正整數時直接 `exit 2`（`... review.html 0` 會一批都不跑然後回傳成功）。

## 3d-2. 兩個共用的檢查模組（`tools/checks/lib/`，2026-09-02 起）

每一課的設定檔原本是**互相複製**出來的，所以一個修好的檢查不會傳到別課去 ——
issue #2 就是這樣：`add-sub`／`time`／`length`／`divide`／`multiply` 這五課的設定檔
**從來沒有讀過 `q.why`**，解釋裡寫錯的算式一路綠燈；而唯一有幾何檢查的 `divide`
因為當初那個事故是「寬度」的問題，寫出來的版本**只驗寬度** —— 一個 `height="1"`
的畫布可以通過所有幾何斷言。

所以這兩個檢查改成**全站唯一一份**，各課 `require` 進來：

| 模組 | 做什麼 |
|---|---|
| `lib/arith.js` | 解釋與題幹裡的算式**逐條驗算** |
| `lib/canvas.js` | SVG 畫布容不容得下它畫的東西（**四個邊**都驗） |

⚠️ **要改就改 `lib/`，不要複製回設定檔。** 複製一份出去就是下一個 issue #2。

### `lib/arith.js` —— 三種「不是宣稱」要分清楚

驗算器最危險的地方不是算錯，是**靜靜跳過**。跳過的每一種都要能說出名字：

- **題目式**：`25 + 34 = ?`、`6 × □ ＝ 18`、`6 × 幾包 ＝ 18`。這些是題目不是宣稱。
  ⚠️ 判準是**這條算式自己的形狀**，不是「附近有沒有問號」——
  鏈的開頭是運算子（左運算元被切走了）而且緊鄰的真的是未知數才算。
  用「附近有沒有」判斷的話兩邊都會出事：
  「小明算 71 － 28 ＝ 57，**對不對？**」句尾的問號會把一條刻意寫錯的算式靜靜放行，
  而「幾**公分** ＝ 100」的兩字量詞又會塞不進窗口，變成假警報。
- **單位換算**：`1 公尺 ＝ 100 公分`。把單位當量詞剝掉會變成 `1 = 100` 被判算錯。
  ⚠️ 正解不是跳過，是**真的換算**（設定檔給 `conversions`）：
  換完是 `100 = 100` 真的驗過，而寫錯成 `1 公尺 ＝ 10 公分` 會被抓到 —— 跳過的話兩種都抓不到。
- **刻意寫錯**：「小明算 71 － 28 ＝ 57，對不對？」課文要孩子找出錯誤。
  設定檔用 `wrongOnPurpose` 明講。⚠️ 兩個方向都要卡死：
  宣告了卻**從來沒對上**（`unmatched()`）是一個永遠擋著的洞；
  而且放行是**整課通用**的，所以連**放行了幾次**（`excuseCounts()`）都要釘住。

覆蓋率要釘**三個**東西，缺一不可：

1. `verified` —— 驗過幾條。一個壞掉的正規化會讓每條算式都靜靜讀不到，那樣也是零錯誤。
2. `questions` —— 幾條是題目式。
3. ⚠️ **驗過的算式本身的指紋**（`verifiedAll()` 排序後取 sha1）。
   只釘數量擋不住「拿掉一條、再補一條」—— 數字一樣，驗的卻是別的宣稱。
   （改壞測試裡就有這一條：把一條正確算式換成**另一條正確算式**，數量完全不變。）

### `lib/canvas.js` —— 讀不懂的一律 fail-closed

- 四個邊都驗，不是只驗右緣。
- ⚠️ 屬性要**錨定在字串開頭或空白之後**。`/width="(\d+)"/` 沒有錨點會先咬到
  `stroke-width="3"`，整個畫布被當成 3px 寬；`\b` 也不夠（`-` 是非字元）。
- ⚠️ 尺寸只讀**根 `<svg>` 自己**的標籤，而且座標是畫在 **viewBox 的座標系**裡 ——
  有 viewBox 就以它為準，不是拿座標去和 CSS 的 width／height 比。
- ⚠️ **width／height 和 viewBox 的長寬比不一樣要報出來**：瀏覽器會把整張圖等比縮小
  再置中，圖就無聲地變小了。（issue #5 的體重計就是這樣：viewBox 加寬到 210、
  width 還寫死 170，錶面縮成 8 成。這條檢查裝上去之後，拿修好前的那張圖去餵它，
  它自己重現了那個缺陷。）`preserveAspectRatio="none"` 是明講要拉伸，不算。
- ⚠️ 「沒寫」和「寫了但讀不懂」是兩回事：沒寫的 `x` 預設是 0 可以放心當 0，
  寫了 `x="abc"` 卻當成 0 的話那個元素會被擺到左上角，畫出界完全看不到。
- ⚠️ 線的粗細要**逐個元素**算。拿全圖最粗的那條去墊每一個元素，一條 12px 的底線
  會讓每個小圖示都多出 6px，好好的圖被誤判成畫出界。
- ⚠️ **emoji 的字寬要數「畫得出來的字」**：`[...'🖍️']` 是兩個碼點（本體＋變化選擇子）
  但只畫一個字；👨‍👩‍👧‍👦 是四個人加三個 ZWJ，畫出來也只有一個。照碼點數會算成兩倍、四倍寬。
- `transform=`、`<tspan>`、巢狀 `<svg>`、`polygon`／`path` 等讀不懂的東西一律**回報**，
  因為那是「沒檢查」，不是「通過」。

`grade-6-circle.js`（圓周率、圓周長、圓面積、周長還是面積）是六年級第五份設定，有四件事值得別課抄過去：

- ⚠️⚠️ **小數的課也不能用 `lib/arith.js`**：那一份看到小數就直接判失敗（它是給整數課寫的），
  而這一課每一句旁白都是小數算式（`10 × 3.14 ＝ 31.4`）。設定檔自己寫了一份 `decArith`，和 `fracArith` 同一個骨架
  （切鏈 → 遞迴下降 → 精確有理數比較 → 逐個等號記帳），只是把 `3.14` 解析成 314/100。
  ⚠️ 收尾的 lookahead 只可以擋「數字還沒讀完」，**不可以擋句末的句點**：`62.8 ÷ 20 ＝ 3.14.` 用 `(?![\d.])` 的話，
  最後一節讀不完會回溯成 `62.8 ÷ 20`，那個等號整條被丟掉 —— 靜靜不驗。正確寫法是 `(?!\.?\d)`。
- ⚠️⚠️ **頁面層的算式檢查不可以掃原始碼**：字典是 JS 字串拼出來的，`' × 3.14 ＝ ' + hText(c)` 在原始碼裡長得像一條斷掉的算式，
  而 `indexOf(v) < 0` 的 `<` 會被標籤正規式當成標籤開頭把後面一段吃掉 —— 兩種都是假警報。要掃的是**兩種真的會被讀到的字**：

  ⚠️ 取字典的結束點要**數大括號**，不可以用「下一行是 `var lang`」——`review.html` 的 `var lang` 在 I18N 前面，那樣會整頁靜靜不檢查。
- **「交給別課的詞」要逐一出現的位置檢查，不是整頁檢查**：整頁檢查的話，同一頁別的地方寫過一次「不在這一課」，
  後來新增的那一句漏寫也照樣綠燈（改壞測試證明過：拿掉字典那一份，markup 那一份還在，整頁檢查抓不到）。現在窗口取前後 160 個字。

  設定檔把每一個座標**重算一次**再逐一比對，最後印成 SVG 餵 `lib/canvas.js` 驗四個邊。切開重排那張圖另外驗**兩邊等面積**
  （長方形的長 × 寬 ＝ 圓的面積，都在 px 的座標系裡），這樣「長是圓周長的一半、寬是半徑」不是文案而是量出來的。

`grade-6-divide-fraction.js`（分數 ÷ 分數、倒數、乘倒數的理由、商的大小）是六年級第四份設定，有四件事值得別課抄過去：

- ⚠️⚠️ **這一課不能用 `lib/arith.js`**（和 `grade-4-numberline` 同一個理由，形狀不同）：那一份只認整數算式，而這一課**每一句旁白都是分數算式**
  （`3/4 ÷ 2/5 ＝ 3/4 × 5/2 ＝ 15/8`）。設定檔自己寫了一份**精確有理數**的求值器 `fracArith`：先用一個「只由數／分數／運算子／等號／空白組成」
  的最長片段切出算式鏈，每一節用**遞迴下降**解析（× ÷ 先於 ＋ －，左結合），再用分子分母整數比較。它**逐個等號記帳** ——
  沒有被任何一條鏈吃掉、而且兩邊都貼著數字的等號要報錯（靜靜跳過等於替它背書）。`CLAIM_PROBES` 28 筆每次重跑。
  ⚠️ 已知的極限（沿用 `grade-6-ratio`）：左邊不是數字的等號（`除數 ＝ 1`）當散文放行 —— 規則表就是那樣寫的，所以四頁一律把「商是 15/8」寫成「是」不寫「＝」。
- **課程明講的四句話是列舉證明，不是文案**：對分子分母都在 1 ~ 12 的**每一對分數（20736 組）**驗
  ⑴ 交叉相乘的除法 ＝ 乘以倒數（兩條不同的路）；⑵ 通分之後分子相除就是商；⑶ **把商算出來和被除數比**，
  正負號必須剛好是「除數和 1 比」的相反（這是把「除數比 1 小，商就比被除數大」整個定義域驗過一次，不是相信頁面的 `quotientSide`）；
  ⑷ 每一個分數乘自己的倒數等於 1。第二套實作走**質因數次方取小**求最大公因數（頁面是輾轉相除）。
- ⚠️ **simgen 的內建「誘答抄題幹」對分數會誤報**：它把題幹裡每一段數字都當成「題幹印出來的數」，可是 `3/4` 裡的 3 和 4 是**分數的零件**，
  不是端出來的量。`stemEchoOk` 因此寫成**逐個值的謂詞**：用 `stemRef` 把題幹重建一次，只有在那個數字**從來沒有以獨立的數出現**在題幹裡時才放行；
  題幹真的印出 3 的時候（`containsUnit` 的被除數）照樣會響。裝上去之後實測 239 種放行形狀，**獨立出現的抄題 0 筆**。
- ⚠️ **退化抽樣會讓兩個選項同時正確**：`sameExpr`（哪一個乘法算式和 a/b ÷ c/d 相等）在 **y ＝ x** 時「翻被除數」和「翻除數」的值都是 1，
  在 **y ＝ 1/x** 時「都不翻」和「兩個都翻」的值都是 1。抽樣池因此排掉這兩種，設定檔另外驗四個算式的**值**兩兩不同（只比字串抓不到）。

`grade-6-ratio.js`（比的寫法、比值、相等的比與最簡整數比、照比例配、按比分配）是六年級第三份設定，有四件事值得別課抄過去：

- **選項的「值」有三種形狀，去重要按值**：比 `a : b` 的值是交叉相乘比（`6 : 9` 和 `2 : 3` 同值）、分數 `n/d`、整數（可帶單位）。
  `optKeyRef` 把三種都化成鍵之後才比；`tools/check_quiz.py` 把 `3 : 5` 讀成「值 3、單位 : 5」，看不到這種等值，所以靜態題的比選項
  由設定檔自己驗。唯一放行同值的地方是反向題 `whichNotEqual`（三個相等的比是設計）—— 用 `genId` 逐支放行，不是整體放行。
- **第二套實作全部走另一條路**：最大公因數用質因數次方取小（頁面是輾轉相除）、兩個比相等比「最簡整數比是不是同一對」（頁面是交叉相乘）、
  對 1~30 的每一對數驗「同乘不變、同加會變（a ≠ b）、化簡階梯每一步除以最小共同質數」，對 810000 組 (a, b, c, d) 驗 sameRatio 兩路一致。
- **從畫出來的格子長條量回來**：上面一列剛好 a 格、下面剛好 b 格、格子一樣大、等距、不重疊、含標籤都在畫布內，印成 SVG 字串（帶兩種語言裡最長的標籤）
  餵 `lib/canvas.js`；標籤太長時 `lib/canvas.js` 的文字寬度估計會響（第一版英文 "little brother: 18 parts (10 sweets each)" 估到 x ＝ 709），
  修法是縮短標籤、不是放寬畫布。
- ⚠️ **`lib/arith.js` 不認得比、分數、字左邊的等號、數字之間以外的 ÷**：`2 : 3 ＝ 6 : 9` 會被讀成 `3 = 6`，`比值 ＝ 前項 ÷ 後項` 會變成斷掉的鏈。
  這一課的 `arithAll()` 先自己驗比的等式鏈（交叉相乘）與分數／除法鏈（有理數逐節比），把名詞用的 `a : b`、`n/d`、`a ÷ b` 拿掉、
  兩邊都不是數字的 ÷／＝ 換成文字，剩下的整數算式才交給共用驗算器；`CLAIM_PROBES` 21 筆每一次都重跑。⚠️ 鏈的開頭不可以緊接在
  運算符號後面（`3 × 4 ＝ 12` 的 `4 ＝ 12` 不是分數鏈），而且減號有三種寫法（`-`／`－`／`−`）都要在名單裡 —— 第一版漏了 U+2212，
  `6 − 4 = 2` 被讀成 `4 = 2` 而誤報。

`grade-6-gcf-lcm.js`（短除法求最大公因數／最小公倍數、互質、應用題該找哪一個）是六年級第二份設定，有四件事值得別課抄過去：

- **第二套實作走另一條路，而且對整個定義域跑**：最大公因數用輾轉相除（頁面是短除法）、最小公倍數用 a × b ÷ 最大公因數、
  「共同的原子」用每一個質數各數兩邊的次方取小的（頁面是多重集合交集）、質因數分解每次除以最大的質因數。
  對 1~100 × 1~100 的**每一對數**跑 `ladderRows`：左邊每一列真的同時整除當時的兩個數而且是最小的那一個、底下互質、
  左邊相乘 ＝ 最大公因數、L 形 ＝ 最小公倍數、最大公因數 × 最小公倍數 ＝ 兩數相乘。課程明講的「相鄰的整數一定互質」
  「兩個不同的質數一定互質」也是逐對驗出來的，不是文案。
- **從畫出來的圖量回來（原子重疊圖）**：每一顆小圓用它到兩個大圓圓心的距離判斷落在「只有左邊／兩邊都有／只有右邊」
  哪一區（整顆都要在裡面或外面，壓在圓邊上算失敗），再和獨立算的三堆逐一比多重集合；小圓兩兩不相疊、都在畫布內、
  印成 SVG 餵 `lib/canvas.js`。一直行放得下幾顆是用參考常數**自己算**的，不是相信頁面註解的 MAX_SIDE／MAX_SHARED。
  對 a < b ≤ 100 的每一對都畫一次；放不下的要 `tooMany` 而且一顆都不畫（fail-closed）。梯子是 HTML 表格，沒有畫布。
- **十二支產生器的題幹全部整句重建**（`stemRef`），六個應用題情境的題幹在設定檔裡另有一份（`scenStemRef`），
  並且把 review.html 的 `SCEN` **跑起來**逐一比對兩種語言 —— 情境改一個字就響。`wordProblem` 的選項帶單位
  （公分／袋／分鐘、cm／bags／minutes，英文的 1 要單數），設定檔對每一個情境、每一種語言各驗一次。
- ⚠️ **`lib/arith.js` 不認得三種形狀**，這一課在設定檔裡先自己處理：餘數式、括號裡的算式、以及**分數**（`42/56`、`1/6`

  —— 頁面的旁白因此一律寫成「最大公因數：2 × 2 × 3 ＝ 12」或「相乘是 12」，不要在標籤後面直接接 ＝。

`grade-4-numberline.js`（數線上的分數與小數）有四件事值得別課抄過去，其中一件是這一課
**不能用共用的驗算器**的原因：

- ⚠️⚠️ **從畫出來的圖把 (M, d, k) 量回來**（`measurePlanRef`）。整數標籤落在哪幾根刻度上
  → 一格被平分成幾份（d）與有幾格（M）；點落在第幾根刻度上 → k。只驗「spec 說什麼」的話，

  它量的不是角度，是**題目的答案本身**。設定檔因此可以問一句別的檢查問不出來的話：
  「圖上標的那個點，和被標成正解的那個選項，是同一個數嗎？」
- ⚠️ **這一課不能用 `lib/arith.js`**。那一份只認整數的算式，而這一課的核心宣稱是
  `分子 ÷ 分母 ＝ 商 餘 餘數`、`7/4 ＝ 1 又 3/4`、`3/10 ＝ 0.3`。實測 `lib/arith.js` 會把
  `9 ÷ 4 ＝ 2 餘 1` 讀成 `9 / 4 = 2` 而**誤報**（餘數的形狀它不認得），也會把小數整條擋掉。
  所以這一課自己寫了一份**精確有理數**的驗算器（`claimProblems`），三種宣稱各自處理：
  餘數式（驗 A ＝ B × Q ＋ R 而且 R < B）、等式、大於小於。
  ⚠️ 它**逐個等號記帳**：任何一個 `=`／`>` 沒有被辨認出來的宣稱吃掉就報錯 ——
  靜靜跳過等於替它背書。驗算器自己有 16 筆 PROBE（8 筆必須零誤報、8 筆必須抓到），
  而且裝上去之前先對頁面上**944 個渲染出來的字串**跑過一次確認零誤報。
  ⚠️ 這件事在 repo 裡查得到的證據是設定檔自己的三條釘樁：`CLAIM_PROBES`（16 筆，
  8 筆必須零誤報、8 筆必須抓到）、`NARRATED_COUNT_REF = 604`（渲染出來的字串條數，
  每一條都要非空）與 `CLAIMS_VERIFIED_REF = 31` ＋ 指紋 —— 每一次 `verify_lesson_data`
  都會重跑。944 那個數字是**裝上去之前**用一支暫存腳本掃全部四頁的字典值算出來的，
  不在版控裡；要重現就照 `narratedStrings()` 的清單再掃一次。
  ⚠️ 第一版把左邊切成運算符號來算，於是 `1 又 2/5 ＝ 7/5` 被誤報（帶分數裡面有 `/`）——
  修法是**先試「整個左邊就是一個值」**，切運算符號是最後才做的事。
- ⚠️ **選項的等值要用有理數** —— 不同的字串可能是**同一個數**，這一課有三組：`7/4` 與 `1 又 3/4`、
  `7/10` 與 `0.7`、`2/4` 與 `1/2` 字串都不同、值一樣（⚠️ 第一版的例子寫成 `3/4` 與 `1 又 3/4`，
  那兩個**不同值** —— 舉例本身錯掉的話，讀者會把守衛的意思學錯，codex 抓到）。這一課另外多一條：要孩子**讀出來**
  的每一個點，餘數和分母必須**互質**，而且不可以剛好落在整數上 ——
  否則 2/4 和 1/2 都是正確的讀法，而這一課明講不做約分。
- ⚠️ **固定寬度的「就近」窗口會被別的句子背書**。HANDOFF 原本用 ±90 字的窗口確認
  「通分」旁邊有「五年級」，於是把那個年級拿掉之後，**後面另一句的「五年級」**替它過關了。
  改成**貼著子句**（那個詞所在子句剩下的部分 ＋ 前面十幾個字）之後才響。
- 順帶：`interDecMax` 的兩個拒絕取樣（「最大的只有一個」、「四個值互不相同」）在它自己的
  抽樣空間裡**永遠不會響**，所以從 `make()` 裡拿掉了 —— 死的拒絕條件不是守衛，是裝飾。
  對應的不變條件留在設定檔（它驗的是 make() 交出來的東西），並在註解裡寫明
  **那兩條沒有獨立的改壞測試**，不要讓下一個人以為它們被證明過。

`grade-4-chain-divide.js`（連除、併式與括號）有四件事值得別課抄過去：

- **算式的第二套實作是「把印出來的字串讀回來算」**（`evalPrintedRef`），不是把同一條代數再寫一次。
  它用**有理數**（分子／分母）不用浮點數，所以「這個誘答的值和正解不一樣」證明得出來，
  而且除不盡也算得出來；全形的 ÷ × ＋ ＝ 和半形的 / * + = 都要讀得懂（中英文用的符號不一樣）。
  ⚠️ 這支求值器同時是**規則的第二套實作**：它就是「乘除同層、從左往右」那條規則。
- **除法的參考實作用重複相減**（`divRef`），乘法用重複相加（`mulRef`）。
  這一課教的「連續除以兩個數 ＝ 除以那兩個數的積」因此是被**兩次獨立的減法迴圈**證明的
  （`chainVsOnceRef` 回報兩邊相不相等、以及是不是都整除），不是把 `/` 再抄一次。
- ⚠️ **產生器的「正解長什麼樣」那一行一定要逐字釘住。** 這一課有四支產生器的選項是**算式字串**；
  把正解那一行改壞之後，去重之後只剩三個選項 → `make()` 回 null → `retry()` 落到保底，
  而保底是對的，於是**所有數值斷言照樣全綠**。改壞測試被完整吸收，只有 `REVIEW_PINS` 擋得住。
  同一件事也發生在「整除」與「a === b」那兩個守衛上。
- ⚠️ **「每一個誘答印出來的除法也要除得剛剛好」是這一課最值錢的一條新斷言。**
  `inexactDivisions()` 把任何一段文字裡的**算式鏈**抽出來、括號先算、再從左往右走，
  每碰到一個 ÷ 就用 `divRef` 驗餘數。裝上去的第一次執行就抓到**兩個靜態誘答**
  （`960 ÷ 16 ÷ 16` 的 60 ÷ 16、`24 ÷ (5 × 8)` 的 24 ÷ 40）和一關遊戲（864 ÷ 20）——
  課程明講「沒有餘數、不用小數」，而孩子是會把每一個選項都算一遍的。
- ⚠️ **中英文的題幹都要逐字釘住。** 只釘中文的話，把英文的
  "Which expression is the same as…" 改成 "…is different from…"、選項與 ans 不動，
  所有檢查照樣全綠 —— 英文那一邊等於沒有人在守。
- ⚠️ **跨頁計數要 `!==` 不是 `<`，而且要連 JS 的區塊註解一起拿掉。**
  只有下界的話，從畫面上拿掉一份、在別處多加一份就過關；而不拿掉 JS 註解的話，
  釘住的可能是自己的註解 —— 這一課的 review 頁原本那一條「除得剛剛好」五次**全部在註解裡**。
- ⚠️ **一個參數守衛和一個一般性斷言講同一件事時，要讓一般性的那條先響。**
  第一版在 `INVARIANTS` 裡同時檢查「c 不可以等於 a」和「四個選項的值必須互不相同」，
  於是後者永遠不是第一個響的 —— 改壞測試會抓到參數守衛，那條真正保護孩子的斷言反而沒被證明過。
  拿掉參數檢查（它留在 `make()` 裡，由 `REVIEW_PINS` 釘住）之後，一般性斷言才被證明。

`grade-4-perpendicular.js`（垂直與平行的作圖與距離）有五件事值得別課抄過去，
其中三件是**守門員自己的洞**（四輪 codex 審查，第四輪乾淨收工）：

- **判斷「垂直」的第二套實作是「量畫出來的圖」，不是再寫一次同一條代數。** 課程頁用**整數方向向量**
  （內積剛好 0）；設定檔從**渲染出來的畫布座標**用 `atan2` 把每一條線的方向量回來，
  要求夾角剛好 90 度（或 0 度）。長度同理：量**畫布上的像素長度**再除以一格幾像素，
  並要求每一個報出來的長度都是**整數公分**（所有要報長度的圖都用畢氏三數擺位）。
  ⚠️ 換算格座標 → 畫布座標**一定要自己寫一份**（`refP`）：呼叫頁面的 `P()` 是拿頁面比頁面，
  兩邊一起錯的時候會一起同意（codex 第一輪抓到）。
- ⚠️⚠️ **「記號是不是直角」和「記號畫在哪裡」是兩件事，而且要比多重集合。**
  一個畫得完美的小方框被搬到別的角落、或該標 A 卻標到 B，只驗形狀與數量的話全部是綠的
  （`grade-4-angle-shape` 就是這樣被鏡射到圖形外面的）。這一課從三個點反推被標記的頂點
  （`m[0] ＋ m[2] － m[1]`），再和「該有記號的那些點」**逐一配對**：
  第一版用「是不是清單裡的某一點」，那會放行「四個記號全部疊在同一點」和「唯一的記號搬到另一個交點」——
  改成多重集合的當下就抓到三處真的擺錯（codex 第二輪）。
  ⚠️ 期望值要用**設定檔自己**算的垂直關係，不可以用頁面的（codex 第三輪：那是拿頁面當自己的神諭）。
- ⚠️ **「處處相等」寫成自己造兩個端點再比，是恆等式不是檢查。** `widthEverywhereRef()` 兩端都是
  自己造的，「全部相等」對它恆真。真正證明「畫出來的兩條線處處等寬」的是沿著其中一條
  **取樣好幾個位置**量到另一條的垂直距離（`renderedGapProblems`）。
- ⚠️ **產生器自己的拒絕取樣會把改壞測試吸收掉。** 把畢氏三數表改成非畢氏、或把「只有一條垂直」
  那一支拿掉，產生器只會多抽幾次然後若無其事地繼續，所有數值斷言照樣全綠 ——
  **定義域整片消失而沒有人響**。這一課因此加了 `REVIEW_PINS`：把取樣空間的那幾行**逐字釘住**
  （抽樣池、兩支分支、四個保底的接線）。⚠️ 並且在註解裡寫明它的極限：那是字面掃描，不是資料流分析。
- ⚠️ **`make()` 不可以回 null，而且要證明得出來。** `retry()` 用完會回 null，simgen 每一批只呼叫一次、
  不重試，null 會讓它 dereference 而當掉（當掉不是「抓到」）。做法：能從抽樣池裡拿掉的拒絕條件就拿掉
  （45 度、(a, b) 組合），剩下的四支給 `retry(fn, fallback)` 一組**手算過的保底參數**；
  然後把四支 case 產生器強制回 null 跑一次 simgen，**證明每一個保底自己也通過所有不變條件**。
- ⚠️ **形狀壞掉要響亮地失敗，不可以安靜地爆炸。** 只在 `planProblems()` 裡 `return` 只離開那一支，
  呼叫端接著 `plan.lines.filter(l => l.kind …)` 還是會丟例外，整份報告變成 stack trace。
  現在旗標掛在回傳的陣列上（`shapeBad`），`checkPlan()` 回報「能不能繼續走訪」，每一個呼叫端都要看它；
  自己重新取圖的畫布迴圈另外用 `planUsable()` 守一次。⚠️ 驗形狀要用**索引迴圈**，
  `some`／`forEach` 會**跳過**稀疏陣列的洞。

  單一筆 find/replace 拿不掉；這一點寫在設定檔的註解裡，真正釘住它的是 SIBLING 計數。

`grade-4-congruent.js`（平面圖形的全等）有五件事值得別課抄過去，其中四件是**守門員自己的洞**（三輪 codex 審查抓到）：

- **全等的參考實作走另一條路。** 課程頁用一張 8 個矩陣的表配雙迴圈的 `sameCycle`；設定檔的八種擺法
  由「轉 90° 幾次 × 要不要先左右翻」生出來，多邊形化成**標準字串**（所有起點 × 兩種方向取最小）再比。
  ⚠️ 兩邊的**索引**要對得上（翻了之後各轉 0／2／3／1 次才是頁面那張表的順序）—— 第一版對不上，
  三個翻法全被判成別的擺法。另外「同一個多邊形反方向繞」這一條路**沒有任何資料會走到**
  （所有圖形都是同一個順序生出來的），要另外用 `P.reverse()` 逼它跑一次。
- **「該用哪一種搬法」只對沒有對稱的圖形有唯一答案**，所以圖形庫的每一個圖形都要證明八種擺法
  畫出來互不相同（`trivialSymRef`）；長方形只准出現在「面積」那一段。
- **字母要驗「貼著它自己的頂點」，不是只驗字母集合是 ABCDEFGH**：每一個頂點都要剛好有一個字母
  在 LABEL_R 的距離上，而且讀出來要是那個頂點該有的字母。字母也要用射線法證明在圖形外面、
  不壓在邊上、彼此的字框不疊（用字框，不是圓心距離）。
- **成對規則（PAIRED）與鍵規則（KEY）都只看字典那一段**：看整個檔案的話，markup 裡的 fallback 副本
  會替字典裡被刪掉的那一句背書。英文字典要用 `enRegion()` 切到 I18N 物件收尾，不可以一路到檔尾。
  HANDOFF 的窗口要**貼著那個詞**（前後幾十字），同一句話後半的「國中」會替前半越界的詞背書。
- **性質先驗、逐字比對放最後**：把 `TRAP` 改成長方形時，「和參考不一樣」不可以是第一個響的，
  「有對稱」才是。`sameAngle` 要有一個**同號但大小不同**的反例（Q2 的兩個銳角），

  ⚠️ 排版類的缺陷（兩個長方形 6 × 4 和 8 × 3 填滿一列黏在一起）是**接觸表截圖**看到的，
  然後才寫成斷言（兩圖中間至少空兩格）—— 第九次「檢查全綠、只有看圖才發現」。

`grade-4-chart.js`（一格代表 1 個的長條圖與折線圖）有五件事值得別課抄過去，其中三件是**守門員自己的洞**：

- **「圖上讀得到的別的數字」不可以當誘答，可是要看題目問什麼。** `readBar`／`linePoint`
  問的就是「讀一條長條」，所以別條的高度**一定**要排除掉（孩子讀錯一條也算讀對了那一條）；

  不是「這個數字在不在圖上」。**
- ⚠️ **「必須提供某個誘答」的斷言會被正解自己滿足。** `diffBars` 的「相加」誘答在
  最少的那一項是 0 時**剛好等於正解**，`opts.indexOf(sum) >= 0` 比中的是正解、照樣放行。

  這一課真正要練的情形整個排除掉（第二輪審查抓到）。最後的做法是：**產生器把
  「這一批有沒有那個誘答」記成一個旗標，設定檔驗旗標誠實 ＋ 該有的時候才要求它。**
- ⚠️ **「幾項」「幾段」的選項一定要帶單位。** 裸數字和圖上讀得到的「幾個」長得一模一樣，

  那是前四輪都沒看到的真缺陷。**代價是要另外釘一張情境名／項目名／單位的真值表**
  （`SCENE_REF`／`ITEM_REF`／`UNIT_REF`），不過那本來就該有。
- ⚠️ **被更強的斷言蓋過去的舊斷言要刪掉，不是留著。** `STEM_EXACT` 上線之後
  `TARGET_PHRASE` 再也響不了，留著就是一條假的覆蓋率 —— 刪掉它，把它的改壞測試
  改指向新的那一條。圖說那三條（子字串／結尾／次數）同理。
- ⚠️ **題庫神諭只釘中文等於只釘了一半。** 英文那一半的題數要單獨數（不然刪掉一題英文
  只會讓 `if (!qe) return` 靜靜跳過），題幹也要單獨釘 —— 不然英文可以問別的運算
  而保留同一個答案。

`grade-4-figurate.js`（三角形數與正方形數）有四件事值得別課抄過去，其中三件是**守門員自己的洞**：

- **參考實作走「幾何」，課程頁走「公式」。** 課程頁算的是 n × n、n × (n ＋ 1) ÷ 2、k ＋ k － 1；
  設定檔一律把**點的座標列舉出來再數**（正方形數 ＝ 數 n × n 格、三角形數 ＝ 一排一排累加、
  第 k 個 L 形 ＝ 數 `max(row, col) + 1 === k` 的格子），對 n ＝ 1~40 逐一比對。

- ⚠️ **圖說不可以把被問的那個數算完。** `triRect` 問「長方形有幾個點」，而圖說原本寫著

  「圖說裡出現正解那個數」。**每一支有圖的產生器，都要問一次「圖說有沒有替孩子把題目做完」。**
- ⚠️ **「安全性質」要排在「等於規格」前面，否則永遠輪不到它。** 「兩個點不可以黏在一起」
  排在「半徑要等於規格」後面的時候，任何把半徑改大的改壞都先撞上等式 ——
  那條安全性質從頭到尾沒有被證明過。同一個形狀在這一課出現三次
  （gapsOf／allSame 要排在 kindOf 前面、獨立算出來的遊戲答案要排在頁面自己那條前面、
  「不可以是同一種圖形數」要排在「是另一種的第幾個」前面）。
- ⚠️ **只釘「驗過幾條算式」擋不住「拿掉一條、再補一條」。** 這一課改成連
  `arithProblems.verifiedAll()` 排序後的 **sha1 指紋**一起釘（`NARRATED_FINGERPRINT`），
  並且用一筆改壞測試證明它會響：把 `n × n ＝ v` 換成**另一條同樣正確的** `n ＋ n ＝ 2n`，
  條數不變、指紋變了。⚠️ 順帶：拿掉註解要換成 `'\n'` 而不是 `''` ——
  換成空字串的話，註解前後的字會接在一起，生出原始碼裡根本沒有的匹配。

`grade-4-pattern.js`（數量模式：找規律、算第幾個）有五件事值得別課抄過去：

- **參考實作走「把模型套上去再生成回來」（fit-and-regenerate），而不是重寫同一組性質測試。**
  頁面用「差都一樣／相除都一樣／差的差都一樣」三個**性質**判斷規律；設定檔把四種模型
  分別套上去、往前生成整串、逐項比對，並回報**有幾種模型套得上**——「剛好一種」本身
  就是一條斷言。它當場證明了倍率 1.5 的整數串（8、12、18、27）與比為 2、3、4、5 的串
  （1、2、6、24、120）都不可以算成「每次乘一樣多」。
- ⚠️ **課程規則的「前提」要單獨驗。** 「第 n 個 ＝ 第 1 個 ＋ (n － 1) × 每次加的數」
  只對「差都一樣」成立，所以設定檔明確要求 mul／grow 那兩種規律
  在 `findIndex` 回 `why:'kind'`、在 `offByOneValue` 回 `null` ——
  少了這兩條，孩子可以把規則套到不該套的地方而全站綠燈。
- ⚠️ **有四筆改壞測試「根本改不壞」，因為更早的守衛已經排除掉那個情形。**
  `kindOf` 裡 `g[0] > 0`／`r[0] > 1`／`gg[0] > 0` 三個界限都被前面的 `dirOf`
  判斷遮住，單獨放寬毫無效果。**看到 NOT CAUGHT 先確認改壞版真的移除了那個性質**，
  再換一個真的破得掉的改法，並補上真正碰得到那個界限的斷言。
- ⚠️ **`SIBLING_RULES` 的 `min` 要寫成當下真實的出現次數，不是「至少 2」。**
  實際有 3 份而只要求 2 份，拿掉一份還是綠的（這一輪被改壞測試抓到兩次）。
- ⚠️ **解釋裡的算式驗算器（`arithProblems`）有三個邊界要處理，否則會靜靜不驗：**
  ① 全形括號**不要**折成半形 —— 折過去之後「括號裡的算式」全部變成不成對，
  整條鏈被丟掉；② `position\s+\d+` 這種正規式要在 `\d+` 後面加 `\b`，
  不然回溯會吃掉多位數的第一位（`position 11 + 1 = 12` 變成 `1 + 1 = 12`）；
  ③ 散文緊貼算式時字元集會把邊界那一個括號吃進來，要把落單的括號**剝掉**而不是
  放棄整條鏈。驗算器自己有 10 筆 PROBE（6 筆必須零誤報、4 筆必須抓到），每次都跑。

`grade-4-multiply-divide.js`（三位數 × 二位數、除數二位數的試商）有五件事值得別課抄過去，
其中四件是**守門員自己的洞**，都是 codex 三輪審查抓出來的：

- **第二套實作要走「另一種演算法」，不是同一條公式再寫一次。** 這一課的第二套實作
  乘法用**數字陣列的卷積**（每一對數字落在 i+j 那一格，最後一次進位正規化），
  除法用**重複減法**（一直減到不能再減），四捨五入到十位則是**看個位那個數字**。
  三條路都和頁面用的算法不一樣，兩邊同意才有意義。
- ⚠️ **課程明講的話（「調商可能要調不只一次」）要證明它在定義域裡真的發生過。**
  設定檔對 89 × 900 組除法窮舉，順便統計「往上調／往下調／調兩次以上／
  猜出來超過 9／商那一位是 0」各出現幾次，任何一項是 0 就報錯 ——
  不然那幾句話只是文案，沒有題目撐得起來。
- ⚠️ **解釋裡的每一條算式都要真的算對，不能只驗「有沒有出現那一句」。**
  `arithProblems()` 把解釋裡的算式鏈抓出來逐條驗算。三個踩過的坑：
  ① 只抓兩個運算元的話，`24 × 18 ＋ 9 ＝ 441` 會被切成 `18 ＋ 9 ＝ 441` 而誤判 ——
  要抓**最長的一條鏈**，而且左邊界要往前跳過空白（「商 ＋ 1 ＝ 22」的 1 前面是 ＋）；
  ② 算不出來就 `continue` 等於替它背書，`5 ÷ 2 ＝ 2` 會靜靜通過；
  ③ 減號有三種寫法（－ U+FF0D、- 半形、− U+2212），少收一種就只驗到半條式子。
  ⚠️ 這種驗算器**一定要先對真實的解釋跑一次確認零誤報**（這一課跑了 480024 條），
  再拿去當守門員。
- ⚠️ **「題幹裡有沒有出現這些數字」擋不住偷加的東西。** 白名單（集合比對）擋得掉
  `213 × 24 ＋ 1`（多了一個 1），可是擋不掉**重複使用既有數字**的
  `324 × 13 …再加 13 呢？`。所以十二題的題幹一律用 `stemExact` **逐字釘死**。
- ⚠️ **標籤只驗錨點等於沒驗**：靠右對齊的長標籤錨在 x=474 也「在畫布內」，
  整串字卻已經跑到畫布左邊外面了。要把 `estTextW` 和 `text-anchor` 一起算進去。

`grade-4-decimal.js`（二、三位小數）有五件事值得別課抄過去，其中三件是**守門員自己的洞**：

`grade-4-angle.js` 是第一份要驗「**畫出來的圖真的是幾度**」的設定，做法有三件事別課沒做過：

- **把畫圖的函式跑起來，再用 `atan2` 把角度量回去。** 量角器的刻度、兩排數字、角的兩條邊
  在課程裡都是純資料函式（`tickList`／`labelList`／`armList`，不碰 DOM），設定檔對
  **1~179 度 × 左右兩種擺法**逐一呼叫它們，從座標量回每一筆的方向。核心那一條是
  「兩條邊之間的夾角必須等於 a」，**外加兩條邊各自的方向也要對** —— 只比夾角的話，
  兩條邊一起轉 1° 完全看不到，可是那時候邊就對不上刻度了（codex 第一輪抓到）。
- **標籤的位置不可以拿它自己回報的 `deg` 當神諭。** 第一版只比 `lb.deg`，
  於是「每 5 度一個、只標到 90」這種改法數量、半徑、配對和全對，上半圈的數字卻整片不見。
  現在有一張獨立的「每 10 度 × 兩排」真值表，每一格都要剛好被填一次。
- **畫布的四個方向都驗**（上、下、左、右）＋ 五張 `.prot` 與一張 `.turnfig` 的 viewBox
  與 CSS 尺寸。⚠️ 但真正抓到「兩排數字擠在一起、0 與 180 互相疊住」的不是任何一條斷言，
  是把頁面**渲染出來截圖看** —— **幾何對不等於看得懂**，收工前一定要看一眼。

`grade-4-fraction.js`（假分數與帶分數）有四件事值得別課抄過去，三件是**守門員自己的洞**：

- **同值選項在分數這一課有三種形狀**，字串比對一種都抓不到：不同分母同值（6/4 和 3/2）、
  兩種寫法同值（1 又 2/5 和 7/5）、沒進位與進位同值（2 又 7/5 和 3 又 2/5）。
  每一個選項都 `parseOpt()` 回 (分子, 分母) 再**交叉相乘**兩兩比。
- ⚠️ **「有沒有提供那個誘答」的斷言會被正解自己滿足。** 設定檔要求「商和餘數放反」
  那一個誘答在選項裡，可是抽到 q ＝ r 時它**就等於正解**，`some()` 會比中正解、斷言照樣綠。
  七支產生器都有這種退化抽樣（codex 第二輪抓到），現在在 `make()` 的 `ok` 條件裡擋掉。
- ⚠️ **NaN／undefined 讓每一條關聯比較靜靜通過。** `barPlan()` 少回傳一個欄位，
  下面十幾條幾何斷言全部變成 `undefined < x` ＝ false。現在比較之前先過 `num()`，
  而且每一個欄位都從版面常數**重算**（`bar.x === FIG_X0 + i × (寬 ＋ 間隔)`），
  不是拿函式自己回報的值互比。分子分母另外要過 `int()` —— 分母 5.5 只驗 `num()` 會過。
- **畫布尺寸要對得上獨立寫死的規格**（`FIG_W_REF` / `FIG_H_REF` / `FIG_MIN_CELL_REF`）。
  只跟自己的 viewBox 與 CSS 互相一致是不夠的：三個一起改成別的數字，檢查還是綠的。

`grade-4-time.js`（24 時制與日時分秒的加減）有五件事值得別課抄過去：

- **規則有兩個說法時，其中一個要寫成「逐格寫死的真值表」。** 這一課的 12 ↔ 24 時制在設定檔裡
  是一張 `READ_TABLE`（0~23 每一格該怎麼說，一行一格），對 0~23 每一格比 `read12`、
  再對每一格反著算回 `to24`，並且把「中午 12 點加 12 會變成 24 時」「半夜 12 點是 0 時」
  兩個反例各自單獨釘一次。拿課程自己的函式當標準答案等於自己比自己。
- **選項要比「換算成同一個最小單位之後的值」，不是比字串。** 「3 小時 75 分」和
  「4 小時 15 分」字串不同、長度卻一樣 —— 兩個都放進選項，孩子算對也會被判錯（§六之二）。
  `optValue()` 把四種形狀（時刻／12 時制說法／今天隔天／時間量）都換成同一個單位再兩兩比。
- **解析出來之後要再「印回去」逐字比對。** `parseOpt()` → `reprint()` → 必須相同。
  這一條一次抓住英文的單複數（1 hour ／ 2 hours）、補零（07:05）與多餘的空白，
  不用另外寫規則。⚠️ 但**格式化壞掉時先響的是 `expectedCorrect`**，所以「印回去」那一條
  只證明得了**錯誤選項**的寫法 —— 改壞測試要挑一個誘答去改。
- **英文的單複數要有一條全站掃描。** `1` 是唯一會出錯的那個值：
  `/\b1 (day|hour|minute|second)s\b/` 掃每一個渲染出來的字串（題幹、解釋、選項、
  範例、遊戲）。這一輪它抓到兩處真的會上線的「1 days」「1 hours」，而六個靜態檢查、
  30000 批模擬、兩輪 sweep 全都是綠的。
- **「產生器有在抽樣嗎」也要驗。** 每一條不變條件都只看 `make()` **回傳**的值，所以把一支
  產生器寫死成一組合法參數，所有斷言都還是綠的、定義域卻整片消失。設定檔因此把
  `review.html` 的參數池宣告逐字釘住，並要求每一支 `make()` 真的呼叫 `pick`／`pickUnused`；
  另外連 `make:`／`fmt:` 的**數量**一起數（光有一行 `{ id:'…',` 的字面文字湊不出一支產生器）。

`grade-4-area.js` 是選項守門條件最完整的一份，四件事值得別課抄過去：

- **「規則」和「習慣」要分開驗。** 這一課教「面積的單位跟著邊長的單位走」，那是規則；
  「小東西用公分、大東西用公尺」是習慣。原本兩者混在一起，結果「這個東西該用哪一個單位」
  這種題目**四個選項都講得通**（codex 第一輪）。現在產生器的題幹一定要把邊長報出來
  （`unitPick stem does not print the side lengths … so the answer would come down to taste`），
  而規則的措辭由 `SIBLING_RULES` 在三頁上釘住。
- **題幹「問的是什麼」要單獨驗一次**（`ASK` 表）。只驗數字的話，把 `rectArea` 的題幹改成
  問周長、正解卻還是面積，所有數字檢查都還是綠的。每一支產生器記一組
  「一定要有的字」與「一定不可以有的字」（例：問面積的題幹裡不可以出現「周長」）。
- **解釋要驗「算式」，不是只驗數字有沒有出現。** 把「長 × 寬」改成「長 ＋ 寬」時，
  每一個要求的數字都還在。現在 `renderCheck` 要求 `why` 裡出現 `w + ' × ' + h`，
  題庫則有 `whyExpr`（例如 `'20 － 6'`）把運算釘住。
- **要有一張「產生器清單」（`GEN_IDS`）。** simgen 只跑「還在的」產生器，所以刪掉一整支，
  它那一組不變條件、`expectedCorrect` 與 `renderCheck` 會一起靜靜消失 ——
  `data.check` 現在會去讀 `review.html`，比對十個 id 一個不多一個不少。
- ⚠️ **`'公分' 是 '平方公分' 的子字串**：拿單位名當斷言永遠是綠的，要比一整句話。
  同理，`SIBLING_RULES` 的「出現次數」除了總數，還要 markup 那一半與字典那一半各自都有。

`grade-4-rounding.js` 有兩件別課沒做過的事，都是為了「守門員自己會不會 fail-open」：

- **課程教的規則有兩個說法，設定檔把第二個說法獨立實作一次再逐一比對。**
  「看目標位右邊隔壁那一位，0~4 捨、5~9 入」與「停在數線上比較近的那一站，
  剛好正中間就往上」是課程明講「答案永遠一樣」的兩件事，所以 `roundByLine()`
  用**比距離**的寫法重寫一遍（完全不看數字），再對 0~20000 的每一個數 ×
  四個目標位，外加每一站的「正中間 ±1」邊界，全部比一次。
  拿課程自己的 `roundTo` 當標準答案，等於自己比自己。
- **SVG 的上下緣也要驗，不是只驗左右。** 「正中間」那一行的基線原本落在
  y ＝ 116，畫布卻只有 112 高，下緣被切掉 —— 六個靜態檢查、30000 批模擬、
  中英兩輪 sweep **全都是綠的**，因為它們只驗了水平方向。現在版面常數
  （`LINE_H`／`LINE_Y`／各標籤的位移與字級）由課程的資料區匯出，`renderS2`
  直接拿它們畫，設定檔則驗上緣、下緣，以及 viewBox 與 CSS 高度有沒有跟著改。
  **教訓：畫布的每一個方向都要有人驗；只驗一半和沒驗長得一模一樣。**

`grade-4-numbers.js` 是目前唯一會**跨頁讀檔**的設定：三頁都在教「位名從右邊數起」，
只驗上課頁等於沒在盯速查卡與家長頁。它用 `process.argv[2]` 推出課程資料夾再讀
`reference.html`／`parents.html`（**不可以用 `__dirname`** —— 那會讀到真的 repo，
改壞測試複製出來的那一份永遠不會被看到，斷言就變成永遠是綠的）。
比對前先把 HTML 註解拿掉，並且比「出現幾次」而不是「有沒有出現」：
中文字串在這些頁面上一定有兩份（markup 的 fallback ＋ 字典），只改其中一份
必須要被抓到。
（`numbers` 與 `multiply` 的設定是 2026-08-26 補的：那兩課在設定檔機制出現之前就上線，
在那之前 `simgen` 對它們會直接報 `no check config`，等於**完全沒有保護**。）

**四頁都會被複製進暫存目錄**（2026-08-26 起）。以前只複製 `index.html` 與 `review.html`，
所以任何針對 `reference.html`／`parents.html` 的斷言在這裡**永遠跑不到** —— 那些斷言等於
沒有被證明過，而「跑不到」和「通過」在輸出上長得一模一樣。是 `grade-2/solid` 那一課
把這個洞挖出來的。三個要注意的地方：

- **改壞的「頁面」和跑起來的「檢查腳本」是兩件事。** 只有 `index`／`review` 各自有一支腳本
  （`verify_lesson_data.js`／`simgen.js`）；`reference`／`parents` 是被 `data.check` 從旁邊
  讀進來的，所以 break 用 `via` 指定由誰去跑，預設 `review` 跑自己、其餘三頁交給 `index`。
  baseline 迴圈的 `['review','index']` 是**檢查腳本**的清單，不是要複製的檔案清單 ——
  混為一談的話會寫出一個看起來對、其實把 baseline 查錯地方的版本（第一版就是這樣壞的）。
- **`via` 只有在「沒寫」時才套預設**：用 `b.via || 預設` 的話，`via:''` 會靜靜地掉進
  `index`，而那一支剛好也噴同一句話時，這一筆會被**誤判成證明過了**。
- **缺頁要報 `[SETUP-FAIL]`，不可以讓 `readFileSync` 直接炸掉整個 run**；
  同理，不認得的 `b.file` 以前會讓 `SRC[b.file]` 是 `undefined`，下一行 `.split` 丟
  TypeError 打死整批結果。要響亮地失敗，不要靜靜地爆炸。

divide 那一課的 57 筆裡有 9 筆是**第一輪 codex 審查抓到的缺陷**補上的守門條件：
選項必須屬於這一題自己的情境（不然糖果題會冒出「5 籃」）、算式誘答要把 □ 解出來
比一次（`k ＋ □ ＝ 總數` 在 k ＝ 2、答案 ＝ 2 時也成立）、字典的單位詞要跟設定檔的
真值表逐字比對（顆 → 棵 抓不到的話，後面每一條渲染檢查都在拿字典比字典）、
例子的數量要是整數（12.5 顆分成每包 2.5 顆會整除也會過範圍）、
SVG 的寬度要蓋住它自己畫出去的最大 x（一開始那一排散落的東西曾經被整段切掉）、
題庫神諭要記下「題幹裡一定要出現的數字」並從那些數字重算答案（位置式神諭
擋不住「把題幹的 12 改成 13」），而且**每一個選項**都要驗形狀，不只是正解。

**檢查腳本自己也會有洞，而且補洞也會補錯**（2026-08-26 length 那一課，第三輪 codex 審查）：
- `cms[q.ans]` 在 `ans` 越界時是 `undefined`，`undefined > 800` 是 false —— 整題沒被驗到卻是綠的。
  **凡是用索引取值再拿去比較的，先驗索引合法。**
- 靠「渲染結果的樣式」判斷該不該檢查（例如用 `rx="8"` 找長條）會 fail-open：
  樣式一改，檢查就整個靜靜消失。改壞測試證明了這件事。現在改成
  `rulerSVG` 直接輸出 `data-from`／`data-to`，**再加一個和樣式無關的第二偵測器**
  （長條矩形的 y/height），兩個都沒中才算「這一題沒有圖」。
- 神諭表（`BANK_EXPECTED`／`BANK_RULER`）只比對「有的題目」的話，**刪掉一題不會有人發現**。
  要連長度一起比。
- 註解寫的推導和旁邊的常數要一致 —— 審查者第一個抓的就是「註解算出 304，你寫 310」。

**兩支都要先用「刻意改壞」的版本驗過會噴錯再拿去跑真檔** —— 現在用 `tools/breaktest.js`
（§3e）跑，清單進版控。**沒響也要追原因**：add-sub 那一輪有一條沒響，
追下去才發現那個保底路徑實際上到不了。

## 3f. 共用 Python 檢查的改壞測試（2026-08-28 起）

```bash
python3 tools/breaktest_checks.py            # 六支全跑
python3 tools/breaktest_checks.py check_i18n # 只跑一支
```

§3e 的 `breaktest.js` 只跑得到 `simgen.js` 與 `verify_lesson_data.js`，也就是
**每一課自己的設定檔**。上面那六支 Python 檢查把關全站 272 頁，在這之前
**沒有任何已進版控的證據證明它們的斷言真的會響**。

這不是理論風險。2026-08-28 才發現 `check_quiz.py` 的等值檢查壞了很久：
`13/5` 被讀成「符號 1、分數 3/5」，於是 13/5 和 23/5 被判成同一個值；
而 `'' in '-−'` 是 True，沒有符號時一律當成負數。**每一次執行都是綠的。**
（把舊解析器重建出來跑一次可以看到：`13/5` 和 `23/5` 都是 `3/5`、`3/4` 是 `-3/4`。）

每一支的改壞清單住在 `tools/checks/py-<checker>.py`，欄位和 §3e 一樣
（`file` / `find` / `replace` / `expect`），另外多一個 `negative=True`：
**改完之後必須「不」噴那一句**。沒有反向的那一半，「把檢查寫得越來越嚴」
會安靜地開始誤報真實頁面 —— 例如 `parents.html` 是全站唯一可以放站外連結的頁，
把 `[EXTERNAL]` 寫太嚴就等於擋掉延伸資源。

紀律和 §3e 一致：先跑原檔（`BASELINE-FAIL`／`NO PROOF`）、`find` 必須剛好出現一次
（`SETUP-FAIL`）、比對只認輸出裡真的出現那一句話。

三種沙箱模式：`files`（只複製 fixture，路徑當參數）、`rootfiles`（只複製 fixture，
根目錄當參數）、`root`（整個 repo 複製一份 —— `check_links` 與 `check_lessons`
要走訪整棵樹才判得出連結與堂數）。

目前 **39 筆全部照預期**：check_i18n 9（含 1 筆反向）、check_quiz 6（含 1 筆反向）、
check_parents 10（含 1 筆反向）、check_links 7（含 2 筆反向）、check_lessons 4、
check_syntax 3（含 1 筆反向）。

harness 自己會分辨四種結果，不可以混在一起：

| 結果 | 意思 |
|------|------|
| `caught (exit N)` | 檢查印出了那一句話**而且**回傳非 0 |
| `SILENT PASS` | 印出來了卻回傳 0 —— 腳本呼叫端偵測不到，等於沒擋住 |
| `CHECKER-CRASH` | 檢查**當掉**了。當掉不算抓到，也不算「正確地保持安靜」 |
| `NOT CAUGHT` | 檢查整個沒反應 |

⚠️ **當掉和「安靜」長得一模一樣**，是這一支最容易 fail-open 的地方：一支只在
某種輸入下當掉的檢查，會讓每一筆反向改壞都看起來像通過。所以 `run_checker()`
一定要回傳（輸出, 離開碼, 有沒有 traceback）三件事，缺一不可。

三件寫這一份時自己踩到、值得記下來的事：

1. **`check_parents` 的日期是從字典讀的，不是從 markup** —— 第一版那筆「拿掉日期」
   改到 markup，完全不會響。**每寫一筆 break 就跑一次，看它到底有沒有響。**
2. **空斷言比沒有斷言更糟**（codex 2026-08-28 抓到 4 筆）：`en.btn:'中'` 那一筆的
   find/replace 根本沒動到 `btn`；`<title>` 中文那一筆 baseline 本來就證明了。
   還有兩筆（13/5 vs 23/5、英文帶分數）其實是被 **baseline 本身**釘住的 ——
   fixture 裡就含有那一組值，舊解析器會讓**原檔**直接 BASELINE-FAIL，比反向改壞更強。
   **判準：問「這一筆如果拿掉，還有什麼會壞？」答不出來就是空的。**
3. **這一支第一次跑硬化版就抓到 `check_links.py` 的真缺陷**：站內連結那一段的略過清單
   是手打的（`mailto:`／`data:`／`javascript:`），漏了 `tel:`／`blob:`／`about:`，
   於是一個合法的 `tel:` 連結會被誤報成「指不到檔案」。現在改成共用 `LOCAL_SCHEMES`。

⚠️ 順帶修掉的另一件事：**六支裡原本有四支印出問題卻回傳 0**
（check_quiz／check_parents／check_links／check_syntax），腳本呼叫端根本偵測不到失敗。
六支現在都 `sys.exit(1 if 有問題 else 0)`。**注意全站跑的時候 i18n 40／題庫 16／
家長頁 29 都是已知的合法例外，所以那三支在真實 repo 上本來就會回傳 1** ——
要看的是行數有沒有偏離基準線，不是離開碼。

## 4. 站內連結

```bash
python3 tools/check_links.py .
```

所有 `href`／`src`／meta refresh 指到的本地檔案都要存在。

**2026-08-26 起還擋「孩子看的三頁出現站外網址」**（teaching-framework §六之一）。
在那之前這條規則**寫在規範裡但沒有任何檢查在盯**：§六之四 只允許 `parents.html` 放站外連結，
可是沒有東西攔得住有人在 `index`／`reference`／`review` 放一個 YouTube 連結，
而那三頁是孩子自己在看的。現在 `index.html`／`reference.html`／`review.html`
出現任何 `href`／`src`／`action`／`poster`／`data` 的**站外網址**就報 `[EXTERNAL]`：
不分大小寫、不只 http(s)（`ftp:` 之類一樣擋）、協定相對的 `//host` 也擋、
CSS 的 `@import`／`url()` 指向站外也擋；`mailto:`／`data:`／`tel:` 這種不離開本機的照舊放行。
`parents.html` **不在這個規則裡**（它就是唯一的例外）。
大寫標籤、`ftp:`、協定相對三種形狀都驗過會噴錯，而且不會誤傷 `parents.html`。

## 5. 瀏覽器實測（**最重要的一個**）

靜態檢查全綠不代表頁面是對的。上一輪有一個 bug 讓 135 頁的修正完全失效，
只有瀏覽器抓得到；這一輪瀏覽器又抓到 3 個靜態檢查看不到的產生器缺陷
（`polygon` 的「60·2°」保底選項、`fraction`／`percent` 兩個等值誘答）。

`tools/paths.json` 是**全站每一頁**的清單（新增一課就要更新）。它由整棵樹掃出來，
但**排除 meta-refresh 轉址頁**（例如 `/grade-5/math/index.html`）—— 那種頁沒有內容可掃，
掃它只會把 sweeper 帶到別頁去。重建：

```bash
python3 - <<'PY'
import json, os, re
skip={'.git','tools','teaching-workspace','node_modules','.claude'}
out=[]
for root,dirs,files in os.walk('.'):
    dirs[:]=[d for d in dirs if d not in skip and not d.startswith('.')]
    for f in sorted(files):
        if not f.endswith('.html'): continue
        rel='/'+os.path.relpath(os.path.join(root,f),'.').replace(os.sep,'/')
        if not re.search(r'<meta[^>]+http-equiv=[\"\']?refresh', open(os.path.join(root,f),encoding='utf-8').read(2000), re.I):
            out.append(rel)
json.dump(sorted(out), open('tools/paths.json','w'), ensure_ascii=False, indent=0)
PY
```

掃描的程式在 `tools/sweep-lib.js`（`sweep.html` 只是載入它的殼）。
**不開瀏覽器也可以跑**——`tools/sweep-run.html` 這個 driver 會自己跑完兩種語言再把結果印進 DOM：

```bash
python3 -m http.server 8765 >/dev/null 2>&1 &
'/Applications/Google Chrome.app/Contents/MacOS/Google Chrome' --headless --disable-gpu \
  --virtual-time-budget=900000 --dump-dom http://localhost:8765/tools/sweep-run.html > /tmp/sweep.html
# 只掃一課： …/tools/sweep-run.html?only=grade-4/math/quadrilateral
```

結果在 `<pre id="out">` 裡（`DONE` 之後三行：zh／en／options，都要是 `clean`）。

開 `http://localhost:8765/tools/sweep.html`，在 console 裡跑：

```js
PATHS = await (await fetch('/tools/paths.json')).json();
await runSweep(PATHS, 'zh');     // 回傳 [] 就是乾淨
await runSweep(PATHS, 'en');     // 兩種語言都要跑
await sweepOptions(PATHS.filter(p => p.endsWith('/review.html')), 10);
```

- `runSweep` —— 每一頁都載入、切語言、點所有模式卡、點完所有試題選項、
  玩過遊戲（提示／下一關／重新開始），收集 JS 錯誤、空的動態容器、
  畫面上看得到的 `undefined`／`NaN`／`<strong>`，
  以及 **SVG 裡的字有沒有被自己的畫布裁掉、有沒有兩個標籤疊在一起**（2026-08-29 起）。

  **「SVG 標籤」那一條的基準線是 0**（2026-09-02 起，295 頁 × 兩種語言）。
  它是 2026-08-29 修 `grade-3/math/perimeter` 時加的 —— 那一頁的
  「寬 4 公分」在線上被裁成只剩「公分」，L 形的兩個標籤疊成「3 公分公分」，
  而當時**六個 Python 檢查、30000 批模擬、瀏覽器 sweep 全部都是綠的**，
  因為沒有任何一條在問「這個字有沒有落在它自己的畫布裡面」。
  和 2026-08-26 的正字畫記同一種：所有檢查都在數東西，沒有一條在看畫出來長什麼樣。

  兩個實作上的坑（都真的踩過）：
  - **一定要用 `getBoundingClientRect()`，不可以用 `getBBox()`。**
    `getBBox()` 回的是元素自己的座標系，不算祖先的 `transform`，
    所以放在 `<g transform>` 裡的字（時鐘的數字）會被誤判成互相重疊 ——
    第一版就是這樣多報了 8 頁。
  - **量不到的元素（`display:none`）只能跳過，那是「沒檢查」不是「通過」。**
    sweep 會先把模式卡、選項、按鈕都點過，讓圖顯示出來再量。
  **issue #5（24 頁）的修法，2026-09-02** —— 兩類問題要分開處理：

  - **被畫布裁掉**：18 頁在 `</body>` 前加同一段 `fitSVG` 修補（每一頁**位元組完全一樣**，
    改的時候 18 頁要一起改）。它量 `getBBox()`，把 viewBox **只往外撐、永遠不縮**。
    三個踩過的坑，每一個都讓它整段失效過：
    - ⚠️ **提前返回一定要留容差。** 寫回去的 viewBox 經過 `toFixed(1)`，
      拿四捨五入後的值和原始浮點數比，會永遠差 0.04 而一直重寫 —— 瀏覽器直接卡死。
    - ⚠️ **MutationObserver 的回呼是 microtask。** sweep 是「點一下、**同一輪**馬上量」，
      microtask 還沒輪到，量到的是還沒撐開的舊框。所以另外掛 window 的
      `click`／`change`／`input`（冒泡階段，畫面已重畫但還在同一輪）**同步**重量全頁。
    - ⚠️ **observer 不可以每次都重量全頁。** 圓規自動播放每 60ms 重畫一次，
      整頁重量會變成一次動畫幾百次 `getBBox()`（每次都強制重排）。
      observer 只重量被動到的那一塊，全頁重量交給上面那三個事件。
  - **標籤自己疊在一起**：修補救不了，一定要改圖自己的幾何。四個判準：
    - ⚠️ **圖自己的 viewBox 不夠大時，要改 viewBox，不要靠修補撐。**
      體重計的刻度數字畫在半徑 `rLabel` 上，本來就超出 `W`；讓修補去撐，
      畫布變寬而 `width`／`height` 沒變，**整個錶面會被等比縮到 9 成**。
      改 `W` 的時候 `<svg width>` 也要跟著 `W`（有兩頁寫死舊值，那會縮到 8 成）。
    - ⚠️ **標籤永遠不可以被推離它標的那個東西。** 圓心的 `O` 被長標籤擠開 42 單位之後，
      畫面上就是 `O` 在標一塊空白 —— **比原本疊在一起更糟**。
      不可以動的標籤要**排在最前面**（推的迴圈只推後面的）。
    - ⚠️ **推開只能沿著每個標籤自己的固定方向**（往圓外），才會單調收斂；
      「往重疊比較少的那一軸推」會兩個互相推回來，永遠收斂不了。
    - ⚠️ **emoji 的字框比 `font-size` 大得多** —— 實測 20px 的 🐸 高 **31px（1.55 倍）**。
      而且判定要「兩個方向都疊到」才算，所以**只拉開直的那一軸就夠**，
      橫的也拉開反而會把最後一個推出畫布外。
  - ⚠️ 這一條只比對**文字對文字**。青蛙壓在數線上、字壓在圓弧上，它一律看不到 ——
    改完一定要**截圖看**（`--headless --screenshot`），不能只看它變綠。

- `sweepOptions` —— 產生器出的題目連按 N 批，檢查選項有沒有
  垃圾字串（`·`、`#`）、字串重複、**值重複**（key 相等且題幹沒說「記得約分」＝ `KEY-EQUAL`，
  最嚴重）。
